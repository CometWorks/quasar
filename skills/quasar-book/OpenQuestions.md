# Open questions

Things the Quasar code leaves unclear, places where the repository's `Docs/` and the code disagree, and features the docs describe that the code doesn't do yet. Found while writing this handbook. Where docs and code disagree, the pages follow the code.

Don't answer these from the handbook. Say the behavior isn't documented, or check the current code. Maintainers: resolve an item in Quasar or its docs, then update the page and remove the item here.

## Installing and running

Pages: [Install on Linux](InstallLinux.md), [Install on Windows](InstallWindows.md), [Docker](Docker.md).

- Docs say a foreground `./Quasar serve` / `Quasar.exe serve` "opens http://localhost:8080 in your browser", but Bootstrap `serve` never opens a browser and launches the worker with `QUASAR_MODE=service` and `QUASAR_OPEN_BROWSER_ON_START=false` (only `ensure-running --open-browser` opens one). Configuration.md agrees with the code. Pages follow the code. Files: `Docs/QuickStart.md`, `scripts/readme-install-linux.md`, `scripts/readme-install-windows.md`, `Quasar.Bootstrap/Program.cs`, `Docs/Configuration.md`.
- Docs say Bootstrap polls the release stream every 15 minutes and self-updates. In code `TryUpgradeBootstrapAsync` only runs from `Updates/bootstrap-update-request.json` (Force activate / coordinated auto-apply); `UpdatesCheckInterval` is parsed but unused in Bootstrap. Is periodic Bootstrap self-update gone on purpose? Files: `Docs/LinuxDeploymentAndUpdates.md`, `Docs/WindowsDeploymentAndUpdates.md`, `Quasar.Bootstrap/Program.cs`.
- `uninstall.sh --system` without `--install-dir` sets the install dir to `/opt/quasar`, while `install.sh --system` from a release archive installs in place (script folder). `sudo ./uninstall.sh --system --purge` from such an install targets `/opt/quasar`, not the real install. Bug? Files: `uninstall.sh`, `install.sh`, `Docs/LinuxDeploymentAndUpdates.md`.
- Release launcher and worker are self-contained single-file builds, yet `install.sh` requires the ASP.NET Core 10 runtime and `install.ps1` requires `Microsoft.NETCore.App` 10.x. Magnetar is framework-dependent on `Microsoft.NETCore.App` 10, and on Linux the launcher needs the system ICU, which the runtime packages bring (a foreground run on a host without ICU stops at once, SE1-0285). Does anything need `Microsoft.AspNetCore.App`? Why does Windows check only NETCore.App while Linux checks NETCore.App plus AspNetCore.App? Files: `Quasar.Bootstrap/Quasar.Bootstrap.csproj`, `install.sh`, `scripts/install.ps1`.
- Windows Bootstrap self-update spawns a detached `Quasar.exe serve --quiet --service` and exits 0, so the Scheduled Task ends. Does the relaunched launcher still belong to the task (can `Stop-ScheduledTask` stop it, does restart-on-failure still cover it)? Files: `Quasar.Bootstrap/Program.cs`, `scripts/install.ps1`, `Docs/WindowsDeploymentAndUpdates.md`.
- Windows `Stop-ScheduledTask` / `uninstall.ps1`: does terminating the task's job object kill the worker and detached Magnetar/DS processes, or do they survive like on Linux (`KillMode=process`)? Is the stop graceful? Files: `scripts/install.ps1`, `scripts/uninstall.ps1`, `Docs/WindowsDeploymentAndUpdates.md`.
- `install.ps1 -User <account>` registers the principal with logon type ServiceAccount, which Windows accepts for built-in service accounts (SYSTEM, LOCAL SERVICE, NETWORK SERVICE). Does `-User` work with a normal local or domain user? Docs say "a specific service account". File: `scripts/install.ps1`.
- `install.ps1` run in place (packaged) copies the entire install folder, including `ManagedRuntime`, `Magnetars` and backups, to `%TEMP%` and back. Intended? Also it overwrites `Quasar.exe` while the task may be running. Files: `scripts/install.ps1`.
- Rerunning `install.sh --install-dir` / `install.ps1 -InstallDir` from a new archive overwrites the installed `appsettings.json` with the default one. Is there a supported manual upgrade procedure for admins who cannot use the Updates page (offline hosts)? Files: `install.sh`, `scripts/install.ps1`.
- PowerShell execution policy / downloaded-file blocking (Mark of the Web) for `install.ps1` from a zip is not addressed anywhere. Is `Unblock-File` or `-ExecutionPolicy Bypass` needed in practice? Files: `scripts/readme-install-windows.md`, `Docs/QuickStart.md`.
- Offline install: Bootstrap accepts a packaged worker at `<install-dir>/WebService/Quasar(.exe)`. Is extracting `quasar-web-*.tar.gz/zip` into `WebService/` a supported offline install path? Not documented. Files: `Quasar.Bootstrap/Program.cs`.
- Docker image is published only on pushes to `main` that create a full release; tag pushes (`v<version>`) also create full releases but no image. Docs say "for every full release". Files: `.github/workflows/release.yml`, `Docs/Docker.md`.
- Docker: **Shutdown Quasar** stops the worker (exit 0) but Compose uses `restart: unless-stopped`, so Docker likely starts it again. What is the intended container behavior of Shutdown Quasar? Files: `docker-compose.yml`, `Quasar/Services/QuasarShutdownService.cs`.
- Docker: `QUASAR_PUBLIC_BASE_URL` becomes `WebServiceOptions.BaseUrl`, which Quasar also passes to managed servers as `QUASAR_BASE_URL`. Is it safe to set it to a public reverse-proxy URL, or would agents then connect through the proxy? Files: `.env.example`, `Quasar/Services/WebServiceOptions.cs`, `Quasar/Services/DedicatedServerSupervisor.cs`.
- Docker: `QUASAR_UPDATES_ENABLED=false` also stops `ClusterReleaseMonitor`. Do UI plugin auto-updates (`QUASAR_UPDATES_AUTO_UPDATE_UI_PLUGINS`, listed in `.env.example`) and cluster package updates work in the container? Can clusters / Quasar.Host local enrollment (systemd units) work from inside a container at all? Files: `.env.example`, `Quasar/Services/ClusterReleaseMonitor.cs`, `Quasar/Services/Plugins/QuasarUiPluginHubCatalogService.cs`.
- Docker image runs as root (no `USER`), but `Docs/Docker.md` talks about "permissions for the container's service account" for the diagnostics folder. Which account is meant? Files: `Dockerfile`, `Docs/Docker.md`.
- Docker backup: should the container be stopped before copying `quasar-data` (open saves, JSON files)? Docs say only "back up as one unit". File: `Docs/Docker.md`.
- Firewall: which per-server ports must be opened for players (game port UDP only, or also the Steam port game+1000)? No doc or script says. Files: `Quasar/Services/DedicatedServerRuntimePreparer.cs`.

## Servers and config profiles

- Clean exit handling contradicts the lifecycle doc. The doc says "Running -> Stopped: clean exit, not requested", but `HandleProcessExitedAsync` restarts on any unrequested exit (exit code not checked) when `RestartOnCrash` is on and the goal is On. With `RestartOnCrash` off, exit code 0 ends in `Stopped` and the reconcile loop starts it again because the goal is still On. Is that intended? The page only says "any unexpected exit" restarts and that a non-zero exit with RestartOnCrash off stays Crashed. (`Quasar/Services/DedicatedServerSupervisor.cs` HandleProcessExitedAsync + ReconcileAsync, `Docs/StateMachines/DedicatedServerLifecycle.md`)
- "Rendered DS config path" (`ConfigFilePath`) is described in the editor as where Quasar writes `SpaceEngineers-Dedicated.cfg`, but `PrepareRuntimeConfigAsync` only reads it as a source and always writes to `<DS app-data>/SpaceEngineers-Dedicated.cfg` (also what Magnetar gets via `-path`). Which is intended? Left out of the pages. (`Quasar/Services/DedicatedServerRuntimePreparer.cs`, `Quasar/Components/Pages/ServerEditorDialog.razor`)
- In-game bans/admin promotions: Quasar replaces `Administrators`, `Reserved`, `Banned` in the DS cfg from the profile on every start. (`DedicatedServerRuntimePreparer.cs` ApplyConfigProfile/UpsertArray, `Quasar.Agent/GameBridge.cs`)
- ConfigProfileChanges.md says "Applied changes go live unless marked restart-required". No restart-required marking or live push of profile changes exists in code; profiles apply only at start. The doc should be corrected (or the feature is planned). (`Docs/StateMachines/ConfigProfileChanges.md`, `Docs/QuasarArchitecture.md` Config flow)

- Architecture doc says "Lifecycle action buttons are hidden during transitionary states, except Stop while Starting"; the UI actually shows Kill (not Stop) while Starting/Restarting. Doc drift. (`Docs/QuasarArchitecture.md` Process Supervision, `Quasar/Components/Dashboard/ServerCard.razor`)

- `RecycleAfterUptimeHours` (health recycle) and per-server `AvoidSimultaneousScheduledRestarts` exist in `server.json` but have no UI; the supervisor uses the global option, not the per-server field.
